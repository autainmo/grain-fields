# Generation Compiler

本文件只负责把上游已经确定的场景、颗粒区域、颗粒预设、配色、轮廓、文字与比例编译成图像生成指令，不重新设计方案。

## 1. 必需输入

- `main_subject`、`background_regions`、`text_zones`、`user_text`、`user_facts`：来自 `01-scene-analysis.md`；
- `transformation_constraints`：来自 `02-transformation.md`；
- `art_direction`：来自 `03-art-direction.md`，必须包含 `grain_region`、`grain_preset`、四方案 `scheme_palette`、轮廓、文字、比例及方案 4 锁定条件。

缺失时返回对应上游补齐，不在本文件猜测，也不重新读取预设库选型。

## 2. 四方案独立编译

每个方案都要形成独立生成指令，不用一个通用 prompt 只换颜色。

## 3. 指令顺序

1. 源图与主体锁定；
2. 原场景内容关系；
3. 2–3 个背景内容区域；
4. 当前方案完整分区配色；
5. 最终颗粒区域；
6. 颗粒预设与中等颗粒尺度；
7. 其他区域的干净关系；
8. 主体轮廓；
9. 文字；
10. 比例与构图；
11. 禁止项。

## 4. 内容分区编译

```text
背景按原图真实内容划分为：
R1 = [...]
R2 = [...]
R3 = [...]（如需要）
边界跟随景物自身的连续边界，不做机械上下 / 左右切割；同一完整主体不得被人为切断。
```

## 5. 配色编译

### 方案 1–3

```text
当前方案采用克制的 [配色方向]：
R1 = [颜色角色]
R2 = [颜色角色]
R3 = [颜色角色，如有]
主体重要固有色 = [保留说明]
文字色 = [颜色]
强调色 = [如需要，仅小面积]
整体控制在 2–4 个核心颜色角色，优先中低饱和与清楚的明度层级，不使用多重霓虹、彩虹配色或复杂色相堆叠。
```

### 方案 4

```text
锁定原图主配色、综合色关系、构图、主体位置、比例和主要景物关系；不得重新配色。只允许不改变综合色的质感、对比与清晰度优化。
```

## 6. 颗粒区编译

必须同时写清“区域大”和“颗粒单元适中”：

```text
将 R[编号] 整个连续背景区域作为核心颗粒区，处理范围成片、完整，不是边角点缀。使用上游已确定的 [颗粒预设名称]。颗粒单元保持中等视觉尺度：正常观看能明显感知颗粒质感，近看可辨认单元，但不得形成抢眼的大方块或巨大几何块。颗粒密度、方向和明暗顺着原区域材质与光影变化，保留该区域的大体轮廓、空间关系和识别特征，使颗粒像从原景物自然生长出来，而不是贴上去的滤镜。
```

必要时补充：

```text
颗粒单元通常处于图像短边约 0.2%–0.8% 的视觉尺度，随内容调整；避免小到只剩噪点，也避免大到形成大像素、拼豆、巨大马赛克砖或巨型块面。
```

## 7. 其他区域

```text
其他背景区域保持相对干净，仅允许少量与原材质一致的轻纹理。核心颗粒区与干净区形成清晰但自然的粗—净、密—疏关系；不要在所有区域同时堆颗粒、装饰或高对比细节。
```

## 8. 主体轮廓

```text
沿主要主体真实外缘添加清晰纯白轮廓线；粗细适中，看得见但不吞没细节。若主体周围大面积白或极浅，则改用当前方案中对比度足够高的单一颜色。禁止霓虹发光、多层彩边。
```

## 9. 文字

- 用户提供文本：尽量原样使用，只调整断行、字号、层级与位置；不得补造事实。
- 用户未提供文本：直接使用 `03-art-direction.md` 的 `text_direction` 与 `auto_text`。
- 主文字放在相对干净区域，避免颗粒最密处。
- 自动文字优先短标题 + 极短说明，不把文字做成新的高信息噪声区。

## 10. 比例与构图

默认保持原图比例与主要构图。用户指定比例时优先通过留白与最小必要裁切适配；方案 4 最大限度保持原构图。

## 11. 禁止项

每个方案至少包含：

```text
禁止机械几何分区；禁止拆分完整主体；禁止细噪点冒充颗粒；禁止大方块、大像素、拼豆、巨大马赛克砖和巨型几何块；禁止玩具感或糖果感颗粒；禁止颗粒覆盖主要文字；禁止多重霓虹和彩虹式配色；禁止无关装饰堆叠；禁止改变主体身份与关键结构；禁止编造事实。
```

方案 1–3 加：

```text
禁止三个方案只做近似色微调；同时禁止为了差异而无限增加颜色和装饰。
```

方案 4 加：

```text
禁止改变原图主配色、构图、主体位置、比例与主要景物关系。
```

## 12. 四图生成策略

1. 编译 4 个独立完整指令；
2. 一次或分次调用图像生成；
3. 每个方案生成 1 张；
4. 不等待二次选择；
5. 生成后进入 `05-quality-control.md`；
6. 失败只修失败方案。
